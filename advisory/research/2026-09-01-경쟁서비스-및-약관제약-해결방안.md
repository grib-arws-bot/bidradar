# 경쟁 서비스 조사 및 약관·법적 제약 해결 방안

> **질문** ① 입찰/사업공고를 분석 제공하는 유사·경쟁 서비스가 있는가 ② 그들은 약관 제약을 어떻게 해결했는가 ③ BidRadar는 어떻게 해야 하는가
> **조사일** 2026-09-01 · 조사자 아키텍트(Cowork)
> **중요도** ★★★ — 사업 성립 여부와 직결

## 0. 결론 세 줄

**① 경쟁은 이미 치열합니다.** 8개 이상의 서비스가 있고, 그중 **클라이원트(Cliwant)는 BidRadar가 계획한 기능의 상당 부분을 이미 제공**하고 있습니다.

**② 법적 제약은 생각보다 가볍습니다.** 나라장터 OpenAPI의 이용허락범위가 **"제한 없음"**으로 명시되어 있고, 조달청은 스스로 "민간 비즈니스 활성화"를 목적으로 조달데이터 80종을 개방했습니다. Tier 1은 완전히 깨끗합니다.

**③ 진짜 위험은 크롤링이 아니라 전략입니다.** 수집 범위 경쟁은 이미 늦었을 수 있습니다. 차별점을 **수집이 아니라 분석 단계**에서 찾아야 합니다.

### 1-2. ⚠️ 클라이원트 — 직접 경쟁자

가장 주의 깊게 봐야 할 서비스입니다. 자사 블로그에 밝힌 기능은 이렇습니다.

| 클라이원트가 이미 하는 것 | BidRadar 대응 기능 |
|---|---|
| **80여 개 기관** 공고 수집 | 설계안 Tier 1~5 (현재 나라장터+α) |
| **LLM으로 150페이지 입찰 세부 요약** | S8 심층 분석 A2 |
| 제출방법·제한조건 **자동 추출** | S8 참여 자격 요건 추출 |
| 원본 첨부파일과 **비교 가능하게 제공** | S8 조문 위치 인용 |
| 제목뿐 아니라 **본문 검색**, OR/AND | S1 검색 |
| **키워드 셋** 저장·재사용 | S7 관심 주제 + 저장한 검색 |
| **업종 필터** — 조달청 등록 인증서 자동 추출 | S9 제품 카탈로그(인증) |
| **일일 정기 이메일 발송** | 뉴스레터 |

**냉정하게 보면 BidRadar가 계획한 기능의 70% 이상이 이미 시장에 있습니다.**

### 1-3. 그럼에도 남아 있는 빈틈

조사 범위 안에서 **어느 경쟁사도 명확히 내세우지 않는 것**이 셋 있습니다.

**① 사전규격공개·공고예정 단계**
경쟁사 소구점은 전부 *"공고를 빠르고 정확하게 찾는다"*에 머물러 있습니다. 클라이원트조차 "단 10분 만에 참여할 수 있는 공고를 찾는다"입니다.
**BidRadar의 논지는 "공고가 뜨면 이미 늦다"입니다.** 사전규격(나라장터)과 접수예정(IRIS)이라는 **한 단계 앞**을 다루는 서비스는 확인되지 않았습니다. → **가장 방어 가능한 차별점**

**② 요구사양 ↔ 자사 제품 대조표**
경쟁사는 "제한조건 추출"까지 갑니다. **"우리 제품이 이 요구사양을 충족하는가"를 항목별로 판정**하는 곳은 없습니다. 제품 카탈로그(S9)를 전제로 하는 기능이라 진입장벽도 있습니다.

**③ 낙찰 이력 기반 승산 추정**
"이 기관 유사 공고를 누가 몇 건 따갔는가"를 근거로 참여 판단을 돕는 기능은 확인되지 않았습니다.

> **⚠️ 조사 한계** 경쟁사 상세 기능은 공개 소개 페이지 기준입니다. 로그인 후 제공되는 기능은 확인하지 못했습니다. 위 세 가지를 "확실히 없다"고 단정하기 전에 **주요 2~3개 서비스를 실제로 유료 구독해 확인**할 것을 권합니다.

## 2. 법적 근거 — 3층 구조

### 2-1. ★ 1층: 공공데이터포털 API — **완전히 안전**

가장 중요한 발견입니다. 직접 확인했습니다.

> **조달청_나라장터 입찰공고정보서비스(`15129394`)**
> **이용허락범위: "제한 없음"**

공공데이터포털 이용정책도 이를 뒷받침합니다.

| 공공누리 유형 | 상업적 이용 |
|---|---|
| 제0·제1·제3유형, AI유형 | ✅ **가능** |
| 제2·제4유형 | ❌ 비상업만 |

- 출처표시는 제0유형 외 **전 유형 의무**
- 제3·제4유형은 변경(가공) 금지 / 나머지는 2차 저작물 작성 가능

그리고 **조달청의 공식 입장이 명확합니다.** 조달데이터 80종을 「조달정보 개방포털」(`data.g2b.go.kr`)로 개방하며 그 목적을 *"민간의 다양한 분석 및 창의적 아이디어와 결합하여 **민간 비즈니스 활성화**에 이바지"*로 명시했습니다.

또한 조달청이 최근 낸 "나라장터 계약정보 악용 범죄 대응" 보도자료를 확인했으나, **사칭 사기 예방에 관한 것이고 API 정책이나 공개 범위 축소는 없습니다.**

> **판정: Tier 1(나라장터 API 계열) + 과기정통부 API 등 data.go.kr 소스는 유료 서비스에 그대로 써도 됩니다.** 원문 전재도 이용허락범위상 문제없습니다. 출처표시만 지키면 됩니다.

### 2-2. 2층: 크롤링 — 판례는 생각보다 관대합니다

**대법원 2022. 5. 12. 선고 2021도1533** (숙박정보 업체 간 크롤링 형사사건, 원심 서울고법 2020노611)

| 쟁점 | 결과 |
|---|---|
| 정보통신망법 침입 | **무죄** — 접근권한을 별도 보호조치로 제한하지 않았음. API URL·명령구문을 누구나 패킷캡처로 알 수 있었음 |
| 저작권법 제93조 DB제작자 권리 | **무죄** — 50여 개 항목 중 3~8개만 수집(양적 상당성 부족), 공개된 정보라 상당한 투자 불필요 |
| **이용약관 위반만으로 위법인가** | ❌ **불충분** — *"보호조치나 이용약관 등 객관적으로 드러난 여러 사정을 종합적으로 고려"* |

**이것이 IRIS 판단의 법적 근거가 됩니다.** IRIS에는 이용약관조차 없고 보호조치도 없으므로, 이 판례 기준으로는 형사 리스크가 매우 낮습니다.

반대 사례도 봐야 합니다. **사람인 vs 잡코리아**는 DB제작자 권리 침해가 **인정**되었는데, 결정적 요소는 셋이었습니다.

- **VPN 우회**
- **정체 미명시**(User-Agent 위장)
- **robots.txt 무시**

### 2-3. 적법·위법을 가르는 6요소

| 요소 | 위법 쪽 | 적법 쪽 |
|---|---|---|
| 보호조치 | 암호화·접속제한 있음 | 없음 |
| 약관 명시 | 크롤링 금지 명확 | 모호하거나 부재 |
| **수집량** | 상당 부분 또는 전체 | **소수 항목만** |
| 정보 특성 | 유료·갱신 검증 투자 | 공개된 일반정보 |
| **접근 방식** | 회원ID 무단사용·VPN 우회 | **누구나 접근 가능** |
| 흔적 | 공통 오류·워터마크 발견 | 없음 |

적법 크롤링 4조건도 정리되어 있습니다 — **목적**(무임승차 아닌 분석·비교), **대상**(공개 원본데이터), **방법**(미러링 아닌 정상 방식), **결과**(보유자 이익 미침해, **아웃링크로 공익 기여**).

### 2-4. ⚠️ 3층: 부정경쟁방지법 — 민사 위험은 남습니다

**같은 사건에서 형사는 무죄, 민사 1심은 부정경쟁방지법 위반으로 불법행위를 인정했습니다.**

> **형사 안전 ≠ 민사 안전.** 향후 분쟁은 부정경쟁방지법 "성과 도용" 쪽에서 다투어질 가능성이 높습니다.

이것이 **"금지 조항이 없으니 마음껏 긁어도 된다"는 결론을 내리면 안 되는 이유**입니다.

## 3. 해결 방안 — BidRadar가 실제로 해야 할 것

### 3-1. ★ 소스를 법적 등급으로 나누고, 시스템이 강제한다

지금 소스 레지스트리(설계안 04절)에는 robots.txt 확인과 약관 체크박스가 있습니다. **그것으로 부족합니다.** 등급을 데이터로 만들고 등급별 동작을 코드가 강제해야 합니다.

| 등급 | 조건 | 시스템 동작 |
|---|---|---|
| **A · 자유** | data.go.kr 등 **이용허락범위 "제한 없음"** | 원문 전재 허용 · 출처표시 자동 삽입 |
| **B · 조건부** | robots 허용 + 명시적 금지조항 없음 (IRIS 등) | **원문 전재 차단(요약만 저장)** · 아웃링크 필수 · 최소 필드만 · 간격 하한 강제 |
| **C · 금지** | robots 차단 또는 명시적 금지조항 (NTIS·S2B·KIAT·SEMAS·NRF·IITP 등) | **활성화 자체를 거부** |

**핵심은 "관리자가 실수로도 위반할 수 없게" 만드는 것입니다.** 지금 설계는 관리자가 체크박스를 누르면 통과되는데, C등급은 체크박스로도 못 켜야 합니다.

### 3-2. 판례가 가리키는 방어책 5가지 — 전부 구현 가능합니다

| 판례 요소 | BidRadar 구현 |
|---|---|
| "정체 미명시"가 유죄 요소 | **User-Agent에 회사명+연락처 고정** (설계안 04-3에 이미 있음 — 유지·강화) |
| "양적 상당성" 방어 | **B등급은 최소 필드만 수집** — 제목·기관·기간·링크. 본문 전문 저장 금지 |
| "아웃링크로 공익 기여" | **모든 공고에 원문 링크 필수** (구현스펙 S1에 이미 있음 — 법적 의미를 문서화) |
| "VPN 우회·보호조치 회피"가 유죄 | **로그인 필요 사이트는 등록 불가** (설계안 04-3에 이미 있음) |
| "robots.txt 무시"가 유죄 | **차단 시 활성화 거부, 우회 경로 없음** (설계안 04-3에 이미 있음) |

**좋은 소식은 설계안이 이미 대부분 갖췄다는 것입니다.** 빠진 것은 **등급 데이터화**와 **B등급 전재 차단**뿐입니다.

### 3-3. 재검증 — robots·약관은 바뀝니다

조사 결과는 **2026-09-01 시점 스냅샷**입니다. 사이트가 약관을 신설하거나 robots를 조이면 어제까지 적법하던 수집이 오늘 위법이 됩니다.

- **분기 1회 자동 재확인** — robots.txt 해시 비교, 약관 페이지 존재 여부
- **변경 감지 시 해당 소스 자동 비활성화 + 관리자 알림**
- `source` 레코드에 `legal_verified_at` · `robots_hash` 보관

### 3-4. ★ 전략적 권고 — 수집 범위로 경쟁하지 마십시오

이것이 이 조사의 가장 중요한 결론입니다.

클라이원트는 **80여 개 기관**을 수집합니다. 인포21C는 **25년**을 쌓았습니다. 지금 시작해서 수집 범위로 따라잡는 것은 **비용이 크고 차별화도 안 됩니다.** 게다가 범위를 늘릴수록 C등급 소스에 손대고 싶은 압력이 커져 법적 위험만 올라갑니다.

**A등급(공식 API)만으로 커버되는 범위를 먼저 확실히 하고, 차별점은 분석 깊이에서 찾는 편이 낫습니다.**

| | 경쟁사 | BidRadar가 가야 할 곳 |
|---|---|---|
| 축 | **얼마나 많이 찾아주는가** | **얼마나 일찍, 얼마나 깊이 판단해주는가** |
| 단계 | 공고 게시 이후 | **사전규격·접수예정** |
| 산출 | 공고 요약 + 조건 추출 | **제품 대조표 + 승산 추정 + 참여 권고** |
| 형태 | 플랫폼 로그인 | **고객별 뉴스레터(B2B2C)** |

세 빈틈(1-3절) 모두 **A등급 데이터만으로 구현 가능**합니다. 사전규격은 나라장터 API에 있고, 낙찰 이력도 API에 있으며, 제품 대조표는 자사 카탈로그가 원천입니다.

### 3-5. ⚠️ 뒤늦게 인식한 위험 3가지

> **경위** Jeffrey가 *"이미 서비스하는 회사가 많다는 건 법적 문제가 없다는 뜻 아닌가"*라고 물었고, 그 질문에 답하는 과정에서 **1~3절 조사가 놓친 영역**이 드러났습니다. 셋 다 크롤링·저작권이 아니라 **유료 뉴스레터라는 형태 자체**에서 나오는 위험입니다.

#### ① 공고에 담긴 담당자 개인정보 — **✅ 결정: 제외 (2026-09-01)**

과기정통부 사업공고 API 응답에 `managerName`(담당자명) · `managerTel`(연락처)이 포함됩니다. 나라장터 공고에도 담당자 정보가 있습니다.

**공개된 정보라도 화면에 보여주는 것과 외부 고객에게 메일로 발송하는 것은 다릅니다.** 목적 외 이용·제3자 제공 쟁점이 생깁니다.

> **결정 — 담당자 이름·연락처는 수집하지 않고 저장하지 않는다.**
> 나중에 빼려면 이미 발송된 이력까지 문제가 되므로 **지금 박아둔다.**
> 담당 부서명(`deptName`)처럼 개인 식별이 안 되는 조직 정보는 유지한다.

#### ② 광고성 정보 수신동의 — 미검토

유료 구독 뉴스레터가 정보통신망법상 **영리목적 광고성 정보**에 해당하는지, 그렇다면 사전 수신동의·수신거부 수단·야간 발송 제한이 적용되는지 **조사하지 않았습니다.** 위반 시 과태료 대상입니다.

구독자가 대가를 지불하고 받는 정보성 콘텐츠는 광고성 정보가 아니라고 볼 여지가 크지만, **확인 없이 단정할 사안이 아닙니다.** 유료 출시 전 법률 자문 항목에 포함해야 합니다.

#### ③ 재배포의 법적 성격 — 미검토

경쟁사는 대체로 **플랫폼에서 열람**하게 합니다. BidRadar는 **메일로 발송**합니다 — 재배포입니다.

- **A등급**(이용허락범위 "제한 없음") — 문제없을 가능성이 높습니다
- **B등급**(IRIS 등) — 다를 수 있습니다. 요약+링크 원칙(3-1절)이 이 위험까지 덮는 구조이므로 **B등급은 특히 원문 전재를 금지해야 합니다**

## 5. 조사 한계

### "이미 하는 회사가 많으니 문제없다"는 추론이 닿지 않는 곳

Jeffrey의 질문에 대한 답을 여기 남깁니다. **핵심 모델(나라장터 데이터를 모아 유료로 파는 것)은 25년간 검증되었습니다.** 다만 아래 넷은 그 검증 범위 밖입니다.

1. **"그들이 하는 그것"이 무엇인지 우리가 모릅니다.** 어느 경쟁사도 데이터 출처를 공개하지 않습니다. 전부 공식 API만 쓰고 있다면 IRIS 크롤링은 "남들도 하는 것"이 아니라 **우리가 처음 하는 것**입니다
2. **"입찰정보 사업"이라는 하나의 법적 지위는 없습니다. 소스마다 다릅니다.** 인포21C의 25년은 나라장터에 대한 증거이지 S2B·IRIS에 대한 증거가 아닙니다
3. **BidRadar가 하려는 것 중 검증 밖이 있습니다** — 메일 재배포, 첨부 규격서 다운로드·파싱, 담당자 정보 취급
4. **생존자 편향** — 분쟁이 났던 업체는 사라졌거나 조용히 합의했을 수 있습니다

### 확인하지 못한 항목 전체

**경쟁사**
- **데이터 출처** — API인지 크롤링인지. 인포21C FAQ는 robots 차단으로 못 읽음. **어느 경쟁사도 공개하지 않음**
- 로그인 후 실제 기능 — "빈틈 3가지"가 진짜인지 미검증
- **요금제·가격대** — 전혀 모름. 뉴스레터 가격 책정 근거 없음
- 고객 규모·매출 — 시장 크기 미상
- 경쟁사 자체 이용약관 — 그들이 재배포를 어떻게 다루는지

**법적**
- **분쟁 이력** — "찾지 못했다"이지 "없다"가 아님
- **`15129394` 외 데이터셋의 이용허락범위** — 방위사업청 건은 시도했으나 실패. K-water·도로공사 미확인
- IRIS 회원가입 약관 — 비회원 공개영역엔 없으나 회원 약관은 미확인
- NTIS Open API 목록 — robots 차단
- **판결문 원문** — 해설 기사 기반. 원문 미확인

**미조사 (3-5절)**
- 광고성 정보 수신동의 적용 여부
- 재배포(메일 발송)의 법적 성격

**근본적으로**
- **법률 자문을 받지 않았습니다.** 이 문서는 판례 해설 기사를 읽고 정리한 것이며 법률 자문을 대신하지 못합니다
